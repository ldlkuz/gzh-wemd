我觉得现在**不要急着考虑 AI**，先把 Theme 自己定义清楚。因为 AI 只是 Theme 的生产者，不应该决定 Theme 的结构。

看了你的现状，我认为最大的一个问题是：

> **Theme 目前是"CSS"，而不是"设计对象"。**

所以很多能力都没法做。

---

## 我建议先重新定义 Theme

我不会把 Theme 定义成模板，也不会定义成品牌规范。

我会定义成：

> **Theme = 一套完整的组件设计系统（Component Design System）**

也就是说，一个 Theme 描述的是：

> **同一种设计理念下，每一个组件应该长什么样。**

例如：

```text
科技主题

H1
H2
引用
提示
总结
时间轴
图片
代码
分割线
CTA
FAQ
...
```

这些组件共同组成了：

**科技主题。**

而不是：

```text
科技主题

↓

一堆 CSS
```

---

# 我建议 Theme 拆成四层

## 第一层：Meta（主题信息）

只是描述主题。

例如：

```json
{
  "id": "tech_blue",

  "name": "科技蓝",

  "description": "适合技术文章",

  "keywords": ["科技", "专业", "未来"]
}
```

这一层以后 AI 可以生成。

---

## 第二层：Design Token（设计语言）

这一层决定：

整个主题遵循什么视觉语言。

例如：

```json
{
  "color": {},

  "typography": {},

  "spacing": {},

  "border": {},

  "shadow": {},

  "radius": {}
}
```

这是全局。

不是组件。

---

## 第三层：Component Library（重点）

这一层我觉得才是 Theme 的核心。

例如：

```text
Theme

↓

Heading

↓

Variant A
```

```text
Theme

↓

Quote

↓

Variant B
```

```text
Theme

↓

Summary

↓

Variant C
```

也就是说：

Theme 里面真正保存的是：

```text
Heading

↓

这个主题下怎么画
```

而不是：

```css
h1 {
}
```

而是：

```json
Heading

{

layout:left-bar,

icon:none,

padding:20,

...

}
```

Renderer 再生成 CSS。

---

## 第四层：Layout Preference（可选）

很多主题其实还有排版倾向。

例如：

商务：

喜欢：

```text
大量留白

小组件

低密度
```

教程：

喜欢：

```text
很多提示框

很多代码

很多表格
```

故事：

喜欢：

```text
引用

图片

分割
```

这部分不是 AI 排版。

而是：

> Theme 给 AI 一个建议。

例如：

```json
{

preferredComponents:[

summary,

quote,

timeline

],

density:"medium"

}
```

AI 可以参考。

但不是必须。

---

# 这样 Theme 就不是 CSS 了

而是：

```text
Theme

↓

Meta

↓

Token

↓

Component Definition

↓

Layout Hint

↓

Renderer

↓

CSS
```

---

# 那 AI Theme 怎么改？

现在：

```text
Prompt

↓

CSS
```

以后：

```text
Prompt

↓

Theme JSON

↓

Renderer

↓

CSS
```

AI 的 Prompt 就会变成：

不是：

> 写 CSS。

而是：

> 请设计一套主题。

输出：

```json
{
  "themeName": "",

  "designConcept": "",

  "tokens": {},

  "components": {
    "heading": {},

    "quote": {},

    "summary": {}
  }
}
```

---

# 我还有一个建议，我觉得会让你的整个架构清晰很多

**Theme 不应该直接拥有 CSS。**

现在你的代码是：

```text
Theme

↓

theme.css
```

我建议改成：

```text
Theme
        │
        ├── theme.json（真正的数据）
        │
        └── render()
                 │
                 ▼
              CSS
```

因为这样：

- 可视化编辑器改的是 JSON。
- AI 改的是 JSON。
- 导入导出的是 JSON。
- 以后即使渲染规则升级，旧主题依然可以重新生成新的 CSS，而不是维护大量历史 CSS。

---

## 我认为最值得你投入精力的改造，不是 AI，而是**建立一个 Theme Schema**。

如果让我来规划，我第一件事不会写 Prompt，而是先定义一个稳定的 `theme.schema.json`。

这个 Schema 应该回答三个问题：

1. **一个主题由哪些组件组成？**（Heading、Quote、Table、CTA、Timeline……）
2. **每个组件允许配置哪些视觉属性？**（布局、装饰、边框、背景、图标、强调方式等）
3. **哪些属性来自全局 Token，哪些属性由组件自己覆盖？**

一旦这个 Schema 稳定下来，你的三个入口——**可视化设计器、AI 生成主题、未来的主题导入导出**——都可以围绕同一套数据模型工作，而不是分别围绕 CSS 工作。我认为这是整个主题系统改造中最关键的一步。
