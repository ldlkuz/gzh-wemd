# 我用 TraeWork 从零做公众号排版工具，还攒了 16 套能直接用的主题

## 一、我是谁，我卡在哪

**个人背景**：我做公众号运营，同时兼职独立开发。日常要给公众号写文章、做排版；另外还维护一个自己的桌面工具项目。

**当前痛点**：

1. **公众号排版又慢又丑**：每篇文章都要在编辑器里手动调字号、行距、配色、卡片，改来改去还是「一眼公众号模板风」，读者没有记忆点。
2. **想要独特主题，但不会写前端**：刷到好看的排版风格，自己只会改字色，一涉及复杂 CSS（圆角卡片、图片上叠字、首字下沉）就抓瞎。
3. **工具想做成桌面版**：网页版够用了，但想打包成 exe 给更多人用、还要自动更新——打包、CI、自动更新这一整套工程问题，一个人啃很痛苦。

## 二、我用 TraeWork 怎么解决的

**模式**：☑ Code ☑ Design

**具体实践步骤**：

**第一步：先搭起「公众号 Markdown 排版工具」主框架**
让 TraeWork 从零实现：Markdown 编辑器 + 实时预览 + 一键复制到公众号。先解决「排版」这个基本盘，Web 版能用了再往上加东西。

**第二步：确立「视觉稿先行」的主题开发流程**
这是最关键的转折。我发现直接让 AI 写主题容易「自由发挥」，于是定了一套自己的流程：

- 我给它看参考视觉稿 HTML（比如一张美食推荐的排版样例）→ 说明要什么风格
- 它按「骨架 + 皮肤 + 扩展槽」的工程方法论，把它实现成一套**内置主题**（结构、样式、数据槽位分离）

**第三步：用这套流程批量产出主题**
按同一个流程，陆续产出了 **16 套内置主题**：美食图谱、好物种草、民宿纪、故事集、数据蓝图、黑金奢华、莫兰迪森林……每套都是完整可用的公众号排版风格，直接套用。

**第四步：桌面版 + 自动更新 + CI 三平台构建**
Web 版稳定后，让 TraeWork 打包成 Electron 桌面应用：

- 接入 GitHub 自动更新（electron-updater）
- 配好 GitHub Actions，打 tag 自动构建 Windows / macOS / Linux 三个平台并发布 Release

## 五、实践经验总结

1. **视觉先行，再让 AI 实现**：先出参考 HTML 视觉稿确认风格，再让 TraeWork 按工程方法论落地成代码，比口头描述「我想要好看点」靠谱得多。设计意图和实现分离，产出的东西才是你真正想要的。
2. **踩坑要沉淀成文档**：微信编辑器一堆隐性坑（position 定位会被删、伪元素会被删、空元素会被删）。我把每次踩过的坑和修法写进一份方法论文档，下次新主题直接对照，不再重复踩。TraeWork 会自动遵循这份「经验文档」。
3. **AI 代码也要「同路径同特异性」**：做主题皮肤时，选择器层级没写对，改了半天导出却不生效——原来是特异性低于共享样式被覆盖。这种细颗粒的坑，让 AI 记住规则比人肉记牢靠。
