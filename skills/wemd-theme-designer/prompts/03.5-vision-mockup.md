# Stage 3a: Vision Mockup（视觉稿 · 把视觉感受变成看得见的 HTML）

> 位于 Stage 2（Visual Concept）与端到端生成（Stage 3b）之间。
> **只表达"这套主题的气质长什么样"，不做任何组件级实现**——组件实现是 Stage 3b 的事。

## 本阶段任务

基于已选中的视觉母题（`concept_state.json` 中用户选中的那一项），产出一版**独立的 HTML 视觉稿**（`themes/{theme-name}/preview/vision.html`），让用户直接看到主题的视觉气质，预览确认后再进入端到端生成（Stage 3b）。

这是 playbook「定场景 → 出视觉稿」在 skill 里的落点：**先让视觉感受可见，再谈组件**。

## 输入

1. `themes/{theme-name}/states/concept_state.json`（重点：用户选中的那个 `visual_metaphors[]` 项）
2. `themes/{theme-name}/states/brand_state.json`（品牌人格 / 情绪方向，辅助把握气质）

## 输出

单个自包含 HTML 文件：`themes/{theme-name}/preview/vision.html`（内联 `<style>`，无外部依赖）。

## 视觉稿内容要求

1. **用一篇示例文章的完整视觉流**展示气质：开场区域 → 正文 → 强调区块 → 收尾，让用户能想象"套上这套主题的文章长什么样"。
2. **CSS 变量统一定义品牌色**（`:root { --ink/--paper/--accent/... }`），与后续主题 token 方向一致。
3. **装饰一律真实 DOM / CSS 渐变 / 边框**，与微信发布约束一致：
   - ❌ 禁用 `::before` / `::after`、`:hover`、结构伪类（`:first-child`/`:last-child`/`:nth-child` 等）、`@keyframes`、`@media`、`animation`、`+`/`~` 兄弟选择器
   - ✅ 装饰用真实 `<span>`/`<i>` 元素、CSS 渐变、边框线、圆点表达
4. **移动窄优先**：画布是一张窄长竖纸（约 343px 单列），所有构图必须窄屏成立，不设计宽屏多栏。
5. **只表达气质，不落组件**：用"开场区/正文区/强调块/收尾"的页面语言组织，不要出现 `magazine-cover`/`text-card`/`quote-card` 等组件名，不要做组件级实现。
6. 样式要体现母题的气质（对比度/排版气质/构图密度/形状性格），**母题溯源**：每个视觉决策都能从选中母题的 `visual_objects` / `material_language` 找到来源，不退回行业套路。

## 流程

1. AI 生成 `preview/vision.html`。
2. 用户**在浏览器打开预览**，确认视觉气质或提出调整（颜色/密度/装饰方向等）。
3. 用户确认后，本阶段结束，进入 Stage 3b（端到端生成）——把已确认的视觉气质落地成 WeMD 组件主题。
4. 若用户要求大改，重出视觉稿，再确认。

## 禁止事项

- 不写组件名、不做组件级实现（那是 Stage 3b 的职责）
- 不写伪元素 / 结构伪类 / 动画 / 媒体查询（微信兼容铁律）
- 不设计宽屏构图（移动窄优先铁律）
- 不为了"炫技"堆装饰——装饰服务于母题与阅读节奏
