# Stage 4: Regression Validation（回归验证 · 对照 playbook 验收清单）

> 位于 AI 端到端生成（Stage 3b）之后、主题交付之前。
> 本阶段不写代码，只**逐条核对**生成产物是否满足验收标准，产出 `themes/{theme-name}/validation.md`。

## 本阶段任务

对照 playbook（`reference/theme-craftsmanship.md`「回归验证要点」）逐条检查本主题的生成产物，把结果写进 `themes/{theme-name}/validation.md`。**有未通过项必须先修再交付。**

先用两个自动化脚本拿到机械证据（对应主程序 VerifyImportFlow.test.ts / defaultThemeDomMatch.test.ts），再人工核对清单：

```powershell
# 1) 包级验证：导入器加载 / renderTheme / #wemd 前缀 / 级联顺序 / 伪元素 / 共享装饰中和
node scripts/verify-theme-package.cjs {theme-name}

# 2) 渲染级验证：导出无伪元素/结构伪类/整篇背景、divider 无双线、callout-pro 无双竖条
#    （需在 packages/core 下执行，或仓库根已装 vitest）
npx vitest run --config ..\..\skills\wemd-theme-designer\vitest.config.ts
```

两道脚本全部通过是清单「无伪元素残留 / 无重复装饰 / 级联正确」等项的打勾依据；有失败项必须先修再继续人工核对。

## 输入

1. `themes/{theme-name}/templates/*.html`（自由骨架模板，声明了哪些结构单元）
2. `themes/{theme-name}/css/{theme-name}.css`（生成的 CSS）
3. `themes/{theme-name}/publish/{theme-name}.html`（公众号发布 = 内联链路）
4. `themes/{theme-name}/preview/vision.html`（视觉稿 = 气质锚点）

## 验收清单（逐条核对，写入 validation.md）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | **骨架装饰存在** | 每个定制骨架组件的装饰元素（badge/glow/line/dot/corner 等）在 `templates/*.html` 中出现 |
| 2 | **配色可读** | 每个深色背景元素文字为浅色（不被共享 `var()` 覆盖成同色系深色）；每个浅色背景元素文字非浅色。逐组件核对，深底深字 / 浅底浅字即不通过 |
| 3 | **未定制组件保持默认** | 未写自定义模板的组件，`templates/` 里**没有**它的文件（回退默认骨架），CSS 里**没有**它的覆盖规则 |
| 4 | **无伪元素 / 结构伪类残留** | `publish/{theme-name}.html` 全内联，无 `::before`/`::after`/`:hover`/`:first-child`/`:last-child`/`:nth-child`/`:not(`/`@keyframes`/`@media`/`animation`/`+`/`~`；`css/{theme-name}.css`（= 打包后 `package/styles/components.css`）允许存在**纯中和规则**（`::before/::after { content: none }`，与内置主题一致），其余禁用模式不得出现 |
| 5 | **与视觉稿一致** | 焦点组件的颜色/装饰能回溯到已确认的视觉稿（`preview/vision.html`），不另起一套 |
| 6 | **整篇无背景** | `#wemd` 容器无 `background-color` / 整篇背景图（背景交给公众号编辑器） |
| 7 | **扩展槽渲染（如有 slotDefs）** | 若主题声明了扩展槽（如封面图/编号拆分），断言内容落到骨架正确槽位，未丢内容 |
| 8 | **降级不丢内容** | 若主题不声明扩展槽，相关内容进 desc/body 兜底，不报错不丢数据 |
| 9 | **微信兼容** | CSS 未用微信不兼容表达；被替代/删除的装饰在 CSS 注释里说明了原因 |
| 10 | **无重复装饰** | 覆盖「共享伪元素装饰清单」组件（callout-pro/divider/pullquote/steps/faq）时已中和共享 `::before/::after`（`content: none` 存于 `package/styles/components.css`）；pullquote 已覆盖共享根元素 `border-left`（非伪元素）；timeline 圆点依赖尺寸无关居中（不自己写 left）；`publish/*.html` 中同一装饰线/条只出现一条（无双竖条/双线、无额外 `wemd-mat` 竖条物化） |

## 输出

`themes/{theme-name}/validation.md`：

```markdown
# 主题回归验证：{theme-name}

| # | 检查项 | 结果 | 说明 |
|---|---|---|---|
| 1 | 骨架装饰存在 | ✅ / ❌ | ... |
| 2 | 配色可读 | ✅ / ❌ | ... |
| ... | ... | ... | ... |

## 结论
- [ ] 全部通过 → 可进入打包交付
- [ ] 有未通过项 → 已说明原因，修正后重新生成再验证
```

## 规则

1. 每一条都要**实测核对产物**，不凭印象打勾。
2. 未通过项**必须先修**（回到对应阶段修正产物并重编译），通过后再进入打包。
3. 验收不通过的主题不允许打包交付。
