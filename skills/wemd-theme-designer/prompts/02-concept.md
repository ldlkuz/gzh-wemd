# Stage 2: Visual Concept

## 输入

读取 `creative/brand_state.json`（上一阶段输出）。

## 任务

基于品牌状态，建立核心视觉概念，输出 Concept State JSON。

设计时参考 `brand_identity.type`（企业/个人创作者/媒体/产品/机构/社区），结合品牌介绍和关键词，推导符合该类型气质的视觉方向。

## 规则

1. 不要输出大段解释，只输出 JSON
2. 概念名称要有独特性，能概括品牌视觉方向
3. **必须先产出视觉母题候选（visual_metaphors），供用户选择**

### ⚠️ 母题不是唯一答案，必须输出 3 个候选

视觉没有唯一答案。同一品牌可以有不同的气质方向。因此本阶段必须产出 **3 个风格迥异的母题候选**，让用户在预览后选择其一，再进入视觉设计与组件映射。

- 3 个候选必须**彼此不同**，覆盖该品牌可能的不同气质（例如同一工业机器人品牌：可以有"精密仪器实验室"的严谨感、"工业控制中心"的效率感、"未来制造基地"的创新感）。
- 每个候选都要写出 `reason`（推导依据），说明它如何从品牌档案的差异化信号推导而来，方便用户理解并选择。
- **原则上**：不得把 3 个候选做成同一母题的微调，必须是从不同信号组合出发的差异化方向。

### 关于视觉母题（visual_metaphor）

视觉母题把抽象的品牌概念**锚定成一个具象、可感知的视觉隐喻**，后续所有视觉语言 token 都必须从它追溯来源。

- ❌ 禁止使用行业风格词：`technology`、`modern`、`blue`、`gradient`、`minimal`、`corporate` 这类宽泛词。
- ✅ 必须给出**图形化、可被视觉化**的具体意象。

### 母题从哪来（推导来源）

母题候选**不是用户直接输入，也不是查行业表得到的**，而是从 `brand_state.json` 里挖掘"差异化信号"推导出来的。逐项读取以下信号：

1. **`avoid`（避开方向）** — 最有力的反向信号。它告诉你"不能像什么"，反向锁定母题。例如 `avoid: ["internet startup style"]` 就排除了一切年轻互联网风母题。
2. **`personality`（品牌人格）** — 决定母题的气质基调。`["meticulous", "precise"]` 倾向精密仪器类，`["playful", "bold"]` 倾向手账涂鸦类。
3. **`desired_impression`（希望别人怎么看）** — 决定母题要唤起什么心智。希望被看作"行业专家"（实验室/知识体系）vs "创新先锋"（未来/探索）vs "长期伙伴"（建筑/基石/秩序），母题完全不同。
4. **`industry` + `customer`（行业 + 客户）** — 决定应用场景。给汽车制造企业（精密产线）vs 给个人消费者（生活方式），母题场景不同。
5. **品牌介绍中的独特故事 + `existing_assets`** — 创始背景、产品独特性、已有 Logo 的几何/线条/色调，是母题最丰富的来源。

**禁止**：不要仅凭 `type`（企业/媒体）或泛化关键词（`innovation`）推导母题——这些是同质化信号，会让所有同行业品牌产出同一母题。每个候选必须组合至少 2 个差异化信号来推导。

#### 创作者模式（`brand_identity.type === "creator"`）的母题来源

创作者输入极少，没有真正的行业/客户，但母题推导机制**同样适用**——只是信号来源不同。此时 `industry` 已被 Stage 1 重映射为创作主题、`customer` 重映射为受众。从以下信号组合（至少 2 个）推导：

1. **`personality`（人格）** — 创作者母题气质基调的主导。如 `激情` → 舞台/聚光灯/演出幕布，`内省` → 深夜书房/私人手记，`幽默` → 漫画/贴纸/涂鸦，`冷静` → 实验室/仪表盘。
2. **创作主题（改写后的 `industry`）** — 决定应用场景。如 `AI 工具评测` → 实验室/控制台，`美妆分享` → 化妆台/梳妆镜，`独立设计` → 工作室/草图板，`独立游戏` → 像素/关卡编辑器。
3. **`emotion` / 内容气质** — 决定情感走向。未来感 → 星云/电路，温暖真实 → 手账/胶片，复古文艺 → 旧报纸/打字机，硬核极客 → 终端/代码雨。
4. **受众（改写后的 `customer`）** — 决定要唤起什么心智。给 `独立开发者`（工具箱/命令行）vs 给 `年轻女性`（梳妆镜/衣橱/口红），母题不同。

**禁止**：不要因为创作者没有行业就退化成 `technology`/`minimal`/`creative` 等泛化母题，也不要把人格简单转成一套通用"创意/灵感"母题。每个创作者都必须从 `personality` + 创作主题的组合推导出**彼此不同**的 3 个母题候选。

### ⚠️ 示例仅用于说明"抽象 vs 具象"的区别，不是规则

下面示范只展示"为什么不能写 `technology`，而应该写一个能画出来的意象"。**它只是对比演示，不是行业映射表、不是标准答案、更不是可复制的模板。**

- ❌ 抽象写法（禁止）：`technology`、`modern`、`blue`
- ✅ 具象写法（示例，仅示范意思）：一家工业机器人公司与其写 `technology`，不如写 `"精密仪器实验室"`，`visual_objects: ["calibration grids", "engineering callouts"]`，`material_language: ["machined metal", "glass gauge"]`。

**禁止事项：**

1. **禁止把任何行业与任何固定母题建立对应关系**。不存在"科技=精密实验室""医药=本草图谱"这类固定映射。同一行业的不同品牌，必须根据各自品牌档案推导出**不同**的母题。
2. **禁止照搬或改写示例中的母题**。每个品牌都必须从 `brand_state.json` 的品牌档案出发，生成该品牌独有的母题，而不是套用示例。
3. 你必须自己判断：这个品牌到底该是什么母题。示例中的意象绝不适用"所有"同类品牌。

## 输出格式

严格遵循 `creative/concept_state.schema.json`，输出以下字段：

- `concept_name`: 独特的概念名称，概括品牌视觉方向
- `core_concept`: 核心概念的一句话描述
- `visual_metaphors`: **3 个母题候选数组**，每个含 `metaphor_name`、`reason`（推导依据）、`visual_objects[]`、`material_language[]`、`motion_character`
- `emotional_direction`: 含 `primary` 与 `secondary` 两个情感方向

`visual_keywords` 不在此阶段输出——它应针对**用户最终选中的母题**，由下一阶段（视觉设计）基于所选母题推导。

（字段结构与类型以 schema 为准，此处不提供完整示例，避免被误当作可复制的模板。）
