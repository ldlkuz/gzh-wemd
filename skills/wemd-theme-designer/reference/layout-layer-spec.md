# AI 排版分层方案：基础(程序) / 杂志(AI) / 固定(用户)

> 目的：把"AI 排版做什么"从设计层面钉死。
> 一句话：**基础层交给程序（确定为原生 markdown/原生结构），杂志层才交给 AI 决定"用不用、怎么用"，固定功能块由用户主动添加，AI 不碰**。
> 这样 AI 职责收窄 → 决策面小 → 出错少、返工少、结果可复现。

---

## 1. 背景与动机

之前的 AI 排版让 AI 对**每个普通标题、每段列表**都做组件决策，导致标题重复、组件错位。根因是把"本该程序稳定识别的基础结构"塞给了 AI 判断。

用户实测（Word 中 AI 通用排版）验证：**基础排根本不难、也不该靠 AI**。因此引入分层：AI 只做"高级别视觉"决策，其余全部确定性处理。

## 2. 分层总则与判别规则

判别一个组件放哪层，只看一条：

> **组件的内容能不能直接从原文拿出来（无需提炼、无需创造、无需外部配置）？**
>
> - **能** → **基础层**，程序确定性处理（本来就是原生 markdown / 原生结构）
> - **不能**（要提炼金句 / 挑数据 / 判断是否适配 / 决定时机）→ **杂志层**，AI 决定"用不用、怎么用"
> - **既非原文直取、也非排版决策**（作者信息、版权、关注条、二维码、系列/相关文章）→ **固定功能块**，用户主动添加，AI 不参与

> 备注：`design_tier`(A/B/C) 描述的是**视觉设计自由度**，与本方案描述的**决策层**（由谁处理）是两个正交维度。两者不对应（如 A 级 `quote-card` 属杂志层，B 级 `section-title` 属基础层）。落定时两个字段都保留。

## 3. 三层组件映射总览

| 层 | 由谁处理 | 覆盖组件 |
|---|---|---|
| **基础层** | 程序（确定性） | section-title、numbered-heading、section-divider、article-section、table、styled-table、code-frame、code-block、image-card、image-grid、image-caption、image-text-row、image-compare、pullquote、divider、two-column-cards、resource-list、timeline、faq、accordion |
| **杂志层** | AI（决定用不用/怎么用） | hero-banner、magazine-cover、quote-card、full-quote、callout-pro、stats-block、cta-card、share-card、end-card、product-card、testimonial-card、brand-sign |
| **固定功能块** | 用户（主动添加，AI 不判） | follow-bar、qr-card、author-card、copyright-notice、series-nav、related-posts、toc-nav、tag-label、divider-fancy |
| 辅助（矛盾时） | — | steps、image-text-row、image-compare、toc-nav 见 §5 模糊件判定 |

## 4. 组件详细用法

### 4.1 基础层（程序，确定性）

| 组件 | design_tier | 内容来自 | 用法 / 触发规则 |
|---|---|---|---|
| `section-title` | B | 原文 `##` 标题 | 程序识别 `##` → 渲染小节标题。**AI 不允许为它做主**。触发：原文章节标题。 |
| `numbered-heading` | B | 原文标题 + 序号 | 程序对"数字开头的标题"自动编 `01/02`。触发：`## 1.` / `## 第一步` 等编号型标题。 |
| `section-divider` | B | 原文 `PART` 段 | 程序识别 `PART 01` 类独立行 → 生成 PART+标题分隔。触发：出现独立 PART 行。 |
| `article-section` | B | 原文段落（引用） | 程序按 `from/to` 引用原文段，**不复制不改写**，是长文正股的容器。触发：正文分段。 |
| `table` | B | 原文 markdown 表格 | 程序解析 `\|` 表格 → 原生表格。触发：原文有表格。 |
| `styled-table` | B | 原文表格 | 与 `table` 同，套主题皮肤。程序取表格原文即可。 |
| `code-frame` | B | 原文代码块 | 程序取 ` ``` lang` 代码 + 可带标题。触发：原文代码块。 |
| `code-block` | C | 原文代码块 | 纯代码，程序取。触发：原文代码块（无标题）。 |
| `image-card` | B | 原文 `![]()` | 程序取图 + caption。触发：原文单图。 |
| `image-grid` | B | 原文多张图 | 程序把连续多图组合成网格。触发：原文连续多图。 |
| `image-caption` | B | 原文图 + 说明 | 程序取图成斜体说明，用于单图。触发：图片后跟说明文字。 |
| `image-text-row` | A | 原文图 + 文字段 | 程序识别"图紧跟文字" → 左右混排。触发：图紧随段落。 |
| `image-compare` | A | 前后/左右两张图 | 程序识别"before/after、前后、对比"类相邻两图。触发：相邻两张关系图。 |
| `pullquote` | B | 原文 `>` 引用 | 程序把块引用提为居中大引文。触发：原文 `>` 引用。 |
| `divider` | C | — | 程序在章节间插入 `---` 分隔。触发：原文 `---` 或章节切换。 |
| `two-column-cards` | B | 原文并列列表 | 程序把"并列的短条目"排成两栏卡片。触发：原文 `<br>` 并列短行 / 成对短语。 |
| `resource-list` | B | 原文清单 | 程序把下载列表/书目/N步法整理为清单。触发：原文为同构列表项（带文件/链接）。 |
| `timeline` | B | 原文时间行 | 程序识别"YYYY-MM + 事件"行 → 时间线。触发：原文成串时间点行。 |
| `faq` | C | 原文问答 | 程序识别"问/答"对 → 折叠问答。触发：原文连续 Q/A。 |
| `accordion` | C | 原文条目 | 程序把问答/条目做成折叠面板。触发：原文多条目。 |

> **设计原则**：基础层组件如果 AI 未显式选用，**程序应依据上面的触发规则自动兜底/直出**，不让内容裸露成裸段落。它们不可作为 AI 的"创造性决策"，只作为"确定性识别结果"。

### 4.2 杂志层（AI 决定用不用、怎么用）

| 组件 | design_tier | AI 决策点 | 用法 / 触发信号 |
|---|---|---|---|
| `hero-banner` | A | 是否用顶图、提炼主副标题/tag | 内容为情感化/营销/品牌文时。提炼 `title/subtitle/tag`，**严禁虚构原文没有的内容**。 |
| `magazine-cover` | A | 是否建封面、提炼标题/副题/描述/注释 | 内容适合杂志封面调性（散文/叙事/品牌刊）时。提炼中英主副+描述。 |
| `quote-card` | A | 哪句是值得放大的金句 | 出现金句 / 金句式单行时。提炼 `text`，可带 `author`。 |
| `full-quote` | A | 哪句够格整行放大、制造停顿 | 关键观点/情绪高潮句。整行主色背景白字居中。 |
| `callout-pro` | A | 哪段是需标记的结论/提示/警告 | 原文有"综上/注意/重要/提醒"等信号。选 `title+body`。 |
| `stats-block` | A | 挑哪几个数据值得强化、怎么分组 | 原文有数字对比/关键指标时。提炼 `items(label+value)`。 |
| `cta-card` | A | 是否加行动号召、文案与按钮 | 营销/转化/报名文时。提炼 `title/subtitle/body`，缺转化意图则不触发。 |
| `share-card` | A | 是否引导分享/转发 | 内容具备传播性且希望互动时。提炼 `text`。 |
| `end-card` | A | 是否温和收尾、致谢措辞 | 结尾需要留余味时。提炼 `title(Thanks)/subtitle`。 |
| `product-card` | A | 是否契合带货、取商品信息 | 原文为商品/带货/测评且有价格/卖点时。填 image/title/price/button 等。**不虚构价格评分**。 |
| `testimonial-card` | A | 是否适合背书、引哪条评价 | 原文含名人名言/客户评价时。取 avatar/name/quote/source。 |
| `brand-sign` | A | 是否放品牌小标、放文首/文末 | 品牌内容或需强化品牌时。用用户提供的 logo/slogan，AI 只定位置。 |

> **设计原则**：杂志层组件是 AI 的**选择题与提炼题**，不是"创造题"。AI 必须**基于原文提炼**，禁止编造原文不存在的数字、人名、评价、价格。输出上限受规范约束（组件 ≤ 200 字，正文严禁复制进其他组件，引用走段落号）。

### 4.3 固定功能块（用户主动添加，AI 不判）

| 组件 | design_tier | 使用方 | 用法 |
|---|---|---|---|
| `follow-bar` | C | 用户 | 关注引导条。用户勾选 `text/buttonText`。 |
| `qr-card` | C | 用户 | 二维码 + 说明。用户上传二维码图片。 |
| `author-card` | C | 用户 | 作者名片。用户填头像/姓名/简介。 |
| `copyright-notice` | C | 用户 | 版权声明。用户填年份/作者/许可。 |
| `series-nav` | B | 用户 | 系列文章导航。用户提供系列名/篇数/前后篇。 |
| `related-posts` | B | 用户 | 相关文章列表。用户提供文章标题/链接。 |
| `toc-nav` | C | 程序生成 + 用户决定 | 目录：程序从标题自动生成，用户选择是否显示。 |
| `tag-label` | C | 程序/用户 | 标签：可用程序从标题提取，用户可覆盖。 |
| `divider-fancy` | C | 程序/用户 | 装饰分隔：程序在章节间用，用户可决定样式。 |
| `steps` | B | 程序 | 有序流程：程序识别编号步骤转步骤条。属基础层，表格中列在此作交叉说明。 |

> **设计原则**：固定功能块**不需要 AI 决策**，也不参与"排版"评分。它们的出现与否由用户显式添加决定，AI 永远不替用户自动塞关注条/版权/二维码——除非用户先放了对应入口。

## 5. 模糊件的判定（边界兜底）

| 组件 | 默认归层 | 判定依据 |
|---|---|---|
| `image-text-row` | 基础层 | 图+文字在原文就是相邻形式，程序可确定性拼接；AI 无需判断内容 |
| `image-compare` | 基础层 | 前后/左右的关系可从图注或相邻位置确定识别 |
| `steps` | 基础层 | 编号步骤是原生 markdown 有序列表的直译，程序识别即得 |
| `toc-nav` | 固定层 | 数据完全由标题自动生成，但"显不显示"是用户习惯，AI 不代加 |
| `tag-label` | 固定层 | 标签通常是用户已有的分类体系，AI 臆造标签会失真 |
| `divider-fancy` | 固定层 | 纯装饰，程序按章可生成，用户可选择样式强度 |

规则：**拿不准时，宁可归基础层（程序确定性）或固定层（用户决定），也不要让 AI 自由发挥**。

## 6. 对提示词与渲染器的影响

### 6.1 提示词（`templatePrompt.ts` 需改）
- 基础层组件：从 AI 的"可选组件决策"里移除，改为"程序自动识别、AI 无需指定"的信号清单。
- 杂志层组件：保留为 AI 的可选题，并强化"提炼自原文、禁止虚构"的约束。
- 固定功能块：明确告知 AI"永远不要替用户添加"。

### 6.2 渲染器（`renderer.ts`）
- 新增基础层的**程序触发展现**：识别原文原生结构（标题/表格/代码/引用/图片/时间线/步骤）→ 自动套对应组件。
- 保持 `article-section` 段落引用 + 兜底 + 覆盖率 100% 不变（这些都是程序层已成立的能力）。
- 基础层与 magazine 层在渲染时若同段落冲突，基础层优先（程序保证稳定），杂志层只在确定方可覆盖。

---

## 7. 落地步骤与验收

1. **提示词**：把 `templatePrompt.ts` 的可选组件按三层重写（§6.1）。
2. **渲染器**：实现基础层程序自动识别（§6.2）。
3. **测试**：新增用例——(a) 纯 `## 标题` 文章只出基础层组件；(b) 有金句+数据文章出杂志层组件；(c) 用户放 follow-bar 时 AI 不重复添加；(d) 覆盖率恒为 100%、标题不重复。
4. **验收判据**：同一篇文章两次运行结果一致（确定性），且无标题重复、无裸段落漏排。
